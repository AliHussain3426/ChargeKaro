Method: source inspection of `client/src` and `server/src` plus executed automated tests/builds. No live browser-click audit of every control was performed; classifications are evidence-based where verified and otherwise marked.

| SD-14 | `client/public/manifest.webmanifest`, `sw.js`, `main.tsx` | PWA | Basic manifest + shell service worker registration in prod | Full offline/install/app experience | **Partially dynamic/static shell** | Files present, build passes | Optional enhancement | Validate install/offline on devices, expand caching strategy |

**Overall:** Core transactional/operational features are primarily dynamic and API-backed in implemented modules. Public content is appropriately static. Payment gateway integration and some profile/edit surfaces require targeted verification or completion. No evidence found of user-facing core flows relying on hardcoded records instead of APIs in the audited modules, but exhaustive UI control verification was not performed.
